How it works

Four steps, on every commit it sees.

  1. Index the code

    Route definitions, each handler's line range, outbound calls and the manifest. Only this index is kept, not the code.

  2. Join it to the metrics

    Endpoints in the metrics carry their route template, which matches a route in the index.

  3. Explain the finding

    With the numbers, the window and the query, and a fix drawn from the handler's code.

  4. Learn from dismissals

    Dismiss a kind of comment and it stops. In the demo, PR #11 skipped the comment dismissed on PR #10.

What Review will not do

Push code

Apart from comments, its GitHub access is read-only.

Keep your code

It keeps only the index of routes and handler lines, per commit.

Guess

Every finding shows the metric and window it rests on. With no matching handler, it says so.

Repeat itself

One dismissal stops that kind of comment on that repository.
