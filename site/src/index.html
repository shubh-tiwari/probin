From a sentence to a chart you can trust

No query language, no dashboard building, and no guessing which metric is the right one. Every query is checked against what your services actually send before you see it.

  1. Instrument with Claude Code

    Run the skill in your repository. It adds OpenTelemetry metrics that follow one convention and writes a manifest of every endpoint and metric.

  2. Ask in plain language

    Mention the bot in Slack or type in the web tool. It asks at most two short questions, then states every other assumption so you can change it.

  3. Keep it, watch it

    Save the chart to a dashboard, or turn it into an alert. Rules stay inactive until a person approves them.

Dashboards that explain themselves

Each panel shows its query, its assumptions and a one-line reading of what the chart says. To change a panel, type what you want.

  • “Split by endpoint, last 24 hours”
  • Share a read-only link, or export to Grafana
  • Prometheus-compatible API and a Claude Code connector

Alerts that wait for a yes

“Alert me if checkout p95 goes above 800 ms” becomes a drafted rule with the query in plain view. Nothing is watched until a person approves it, and editing a rule sends it back for approval.

  • Suggested rules when a new service first sends data
  • “Why did this happen?” with the charts behind the answer
  • Uptime checks on your own URLs, from a sentence

A reviewer that has read your metrics

Review connects to GitHub and reads your code alongside live traffic. It ranks the slowest endpoints, points at the line in the handler, and suggests a fix.

  • Comments on pull requests that touch hot paths
  • Follows up after a deploy if latency moved
  • Maps the calls between your services

How Review works

Built to be checked, not trusted

A model that guesses metric names produces charts that look right and are wrong. These rules are enforced in code, not in a prompt.

No invented metrics

Every name in a query must exist in your catalog. A query that mentions anything else is refused before it runs.

Tested before you see it

Each query runs against your data first. If it returns nothing, it is rewritten or you are told plainly that nothing matches.

Your data stays yours

Every query is rewritten to your workspace when it is parsed, and the metrics store enforces it a second time.

One flat price

Priced per workspace, not per seat, with a free trial. Dashboards keep working even if the model budget runs out.

Run the whole thing on your laptop

One command starts the stores, every service, two instrumented demo services with traffic, and local stand-ins for Slack, GitHub and Stripe. No accounts or keys needed. 

$ git clone {{REPO_URL}}.git
$ cd {{REPO_SLUG}} && make dev
$ pnpm ask "latency graph of checkout service in last 5 hr"
# then open http://localhost:8094 and sign in with the local Slack

Needs Node 22, pnpm, Docker and Make. With no model key, a built-in stand-in answers common requests, so nothing costs money. Add an OpenRouter key to use real models.
