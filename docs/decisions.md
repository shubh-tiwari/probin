# Decisions

Choices made while building, where the [build plan](build-plan.md) left room. Each
"default" below follows the plan's rule: keep it unless there is a concrete reason
to change it, and say so in the pull request when you do.

The plan's "Fixed decisions" are not repeated here. They are settled.

### Findings to carry into phase 1

**Stored metric and label names**, as observed in VictoriaMetrics on 2026-11-18 for the demo service.
This is the plan's open item "exact stored metric and label names". The plan's example panel query
runs unchanged against them.

| OpenTelemetry name                              | Stored names                                                    | Labels                                                                                                                      |
| ----------------------------------------------- | --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `http.server.request.duration` (histogram, `s`) | `http_server_request_duration_seconds_bucket`, `_sum`, `_count` | `http_request_method`, `http_response_status_code`, `http_route`, `url_scheme`, `network_protocol_version`, `le` on buckets |
| `orders.completed` (counter, `{order}`)         | `orders_completed_total`                                        | `payment_method`                                                                                                            |
| every metric                                    |                                                                 | `workspace`, `service_name`, `job` (equal to `service_name`), `otel_scope_name`, `otel_scope_version`                       |

Rules seen in the mapping: dots become underscores; a unit of `s` adds `_seconds`; a counter adds
`_total`; an annotation unit such as `{order}` adds nothing.

**Telemetry export is not an outbound call.** With HTTP auto-instrumentation on, a service's own
OTLP export shows up in `http.client.request.duration` with the collector as `server.address`.
The demo service filters it out. The skill must do the same in every language, or the service map
in phase 5 will show every service calling the collector.

## Phase 1

### Design choices

| Area                            | Choice                                                                                                                                                                                        | Reason                                                                                                                                      |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| The agent loop                  | Code runs the plan's "get a metric" sequence; the model is called only to parse the request and to write the query                                                                            | Questions, the two-question limit, defaults, retries and escalation are then rules in code, testable without a model                        |
| Catalog grounding               | `apps/agent/src/agent/grounding.py` parses every generated query and refuses any metric or label the catalog search did not return, and any selector without one exact metric                 | "Validate this in code, not in the prompt"                                                                                                  |
| Workspace isolation for metrics | `packages/promql` rewrites every selector to add the workspace label and refuses any query that mentions the label or uses `info()`; VictoriaMetrics also gets `extra_label` as a second lock | Two independent locks; the rewrite fails closed                                                                                             |
| Ingestion                       | `apps/ingest` checks the key and forwards OTLP to a private collector with a trusted header; the collector stamps the label and drops anything without it                                     | A sender can never choose its workspace                                                                                                     |
| Query windows                   | Range queries end at the present and send `nocache=1` to VictoriaMetrics                                                                                                                      | The store otherwise rounds the window down to the step, hiding up to a step of the newest data. Results are cached in the Query API instead |
| No model key                    | A built-in stand-in (keyword rules, query templates) answers through the same router                                                                                                          | The whole product runs and is tested end to end at no cost                                                                                  |
| Model eligibility               | The router uses only models listed in `evals/eligibility.json`, written by the test set                                                                                                       | "Eligible only if it passes the test set". With a key, nothing runs until the file exists                                                   |
| Open requests                   | Kept in the agent's memory for an hour                                                                                                                                                        | Enough for the CLI; state is plain data so Slack (phase 2) can move it to Postgres                                                          |

### The skill test

Two fresh agents were each given only the built skill and one uninstrumented baseline
service (Node/Express and Python/FastAPI) and asked to set metrics up. Both services
then passed `pnpm conformance` on the running stack. Their reports found problems in the
skill, now fixed:

- Node guide: `metricReader` is ignored by `@opentelemetry/sdk-node` 0.301; it must be
  `metricReaders: [...]`. Following the guide literally exported nothing for a minute.
- Node guide: the bootstrap also set up log export, and its SIGTERM handler cut off
  in-flight requests. Both removed.
- Node: the default resource detectors send the host name and OS user name. The guide now
  restricts them to `envDetector`; the skill now forbids machine details.
- Python guide: the FastAPI instrumentation also emits three HTTP metrics outside the
  convention and measures FastAPI's docs pages; the guide now drops both. Its
  `excluded_urls="healthz,readyz"` example was an unanchored regex that could drop real
  endpoints.
- The rule "no service name in the metric name" contradicted the guide's own examples
  (`inventory.stock.level`). Examples fixed, and the convention checker now enforces it.
- Clarified: where `OTEL_SERVICE_NAME` goes, how to load a local `.env`, extra HTTP
  attributes are fine, unmatched requests have no `http.route`, how to check outbound
  metrics locally, and the job-timing rules for asyncio and self-handled failures.

`scripts/test-skill.sh` repeats the test with `claude -p`. It has not been run.

### Query test set, stand-in model, 2026-11-18

52 cases (45 expect a panel, 7 expect "nothing matches"). First-attempt dry run: 45 of 45.
Fully correct: 49 of 52. Names outside the catalog delivered: none. Rules broken: 0.

The three misses:

- `inventory-stock-one-warehouse-stat` and `inventory-restock-runs-by-result`: stand-in
  limits (it does not filter by a label value, and reads "runs per second" of a histogram
  as a percentile). A real model is expected to handle both.
- `nomatch-database` ("slow database queries on checkout"): catalog search treats "slow"
  as request latency and offers the HTTP histogram. This is in code, not the model; it
  needs a decision on how strict search should be before phase 2.

**None of these numbers say anything about the gate.** The stand-in's templates were
written alongside the cases.

## Phases 2 to 4

Built on request without waiting for phase 1's 90% gate, which needs a model key. Slack, GitHub and Stripe are used through local fakes until real credentials exist.

| Area                      | Choice                                                                                                                      | Reason                                                                                                           |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Slack                     | Bolt for JavaScript with our own install flow and an `authorize` function; tokens sealed with AES-256-GCM                   | Multi-workspace install without Bolt's file stores; tokens never stored in clear                                 |
| Web tool                  | Server-rendered pages (Hono JSX) and one small script, not React                                                            | Same chart renderer as the Slack images, no build step, works without JavaScript. The plan's React was a default |
| Charts                    | Our own SVG renderer, rasterised with resvg for Slack                                                                       | One renderer for both surfaces; series differ by dash and pattern as well as colour                              |
| Open requests             | Kept in Postgres (`agent_requests`)                                                                                         | A Slack thread can be answered hours later and after restarts                                                    |
| Resolved-request cache    | Same words (ignoring case and spacing) reuse the tested query while the catalog of its services is unchanged; still dry-run | “A repeated request reuses the saved query; only data is refetched”                                              |
| Alert engine              | Our own evaluator over the Query API, not vmalert rule files                                                                | Every evaluation is scoped to its workspace by the same code as every query                                      |
| Rule status               | `disabled` added for discarded or switched-off rules                                                                        | History is kept; append-only                                                                                     |
| Collectors                | HTTP checks only; results ingested under the `checks` service                                                               | The only source the plan names                                                                                   |
| Billing                   | Stripe Checkout and webhooks; status changes only through verified webhooks                                                 | The plan's hosted billing provider                                                                               |
| Grafana                   | Export plus a token-authenticated Prometheus API at `/api/prom`                                                             | The export needs a data source that respects workspace isolation                                                 |
| Connector for Claude Code | An MCP server over a read-only token API                                                                                    | Runs on the developer's machine; cannot change anything                                                          |

### Found while building

- Collector URLs must be refused when they resolve to loopback, link-local (cloud metadata) or private addresses, and checked again on every fetch. The first version let development's “private networks allowed” setting open link-local addresses too; the phase 4 check caught it.
- VictoriaMetrics rounds a range query's window down to the step unless caching is off for that request, which hid up to one step of the newest data. The Query API sends `nocache=1` and caches results itself.
- Unitless gauges are stored with a `_ratio` suffix (`http.check.up` → `http_check_up_ratio`); the catalog's name mapping already predicted this.

## The agentic code in Python

The agent, the model router, the connector for coding agents and the query test set runner are
Python. Everything else stays TypeScript.

| Decision                  | Choice                                                                                       | Reason                                                                                                                                                                                                                                |
| ------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Language for agentic code | Python 3.13                                                                                  | The agent's hard work is prompts, evaluation and model behaviour, where Python's tooling is strongest. Chosen over Go.                                                                                                                |
| Tooling                   | uv workspace (root `pyproject.toml`); ruff; mypy `--strict`; pytest                          | One lockfile (`uv.lock`), fast installs, strict types                                                                                                                                                                                 |
| Agent service             | FastAPI and uvicorn, on one dual-stack socket                                                | The same routes, auth, status codes and error bodies as before, so Slack and the web tool did not change. One socket serves IPv6 (Railway's private network) and IPv4 (health checks)                                                 |
| Agent state               | Plain JSON dictionaries in the same camelCase shape                                          | Stored requests and `trace` stay byte-compatible with the TypeScript callers (`packages/agent-client`)                                                                                                                                |
| Shared rules              | Served by a new internal TypeScript service, `apps/platform`                                 | Catalog search and ranking, PromQL analysis (the parser that also scopes queries to a workspace), spec validation, the versioned stores, memory and the unsafe-URL checks keep one implementation each, so two languages cannot drift |
| Small helpers             | Re-implemented in Python (`packages/pycommon`)                                               | Durations, value formatting and JavaScript's number rules. `testdata/*.json` holds the shared cases; both test suites run them                                                                                                        |
| Agent tests               | Ported case for case; ranking, analysis and validation come from `scripts/py-test-oracle.ts` | The tests exercise the real TypeScript rules without a running stack                                                                                                                                                                  |
| Product name in Python    | Read from `packages/config/src/product.ts` at runtime                                        | The name stays in its one constant                                                                                                                                                                                                    |
| Connector                 | MCP Python SDK 2 (`MCPServer`), over stdio                                                   | The phase 4 check launches it as a process, the way a coding agent does                                                                                                                                                               |

Parity checks made before the TypeScript agent was removed: the stand-in parsed 69 requests
identically in both languages; the prompts were byte-identical; the query test set gave the
same result (49 of 52, the same three known misses, every first attempt passing the dry run).
